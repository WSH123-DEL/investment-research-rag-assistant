# 研报分析助手 v3

## 使用

在 PyCharm 中使用 `pythonproject8` Conda 解释器运行 `main.py`，打开
http://127.0.0.1:7860 。如果之前的服务正在运行，先正常停止，再启动新版本。

1. 选择本次研究需要的 PDF，点击“处理本次文件”。
2. 核对每份文件的有效页数、文本字符数和文本块数。无文字页会明确提示，扫描件需先 OCR。
3. 提问时可以带上公司或报告名，例如“根据 Figure AI Report，介绍公司并分析融资、估值口径、风险和数据矛盾”。
4. 选择“深入分析”会开启模型思考，增加可用输出预算。它更慢且有更多 API 用量。
5. 展开“本次检索证据”检查实际送入模型的原文。答案引用使用 `[1]` 等编号，指向真实 PDF 页。

重新处理文件会重置当前浏览器会话的知识库和聊天历史。不同浏览器会话各有自己的知识库。
重启应用后需重新处理文件；本次版本不自动恢复历史知识库。

## 修复内容与取舍

- 旧版会扫描 `data` 整个目录，把历史 PDF 和重复副本混入，却只显示刚复制的文件数量。
  现在只索引传入的上传文件路径，按内容校验值去重；原有 `data` 和磁盘 `chroma_db` 保留。
- 文件逐页提取时保留行列分隔；同时核对普通提取的正文量，版面模式返回空文本或漏掉
  超过约 15% 的非空白字符时回退并提示，防止中文字体造成无声漏页。然后采用
  1,200 字符分块、180 字符重叠。先做普通向量检索，再结合轻量 BM25
  关键词排序、中文问题的英文主题词扩展和文件名实体命中；不使用曾触发原生崩溃的 MMR。
- 用户点名的短报告（最多 14 页、18,000 字符）优先整份提供，保留介绍页、表格和附注。
  其他候选按页补充；上下文字符预算为标准 26,000、深入 36,000。超长页提供相关分块节选。
- 明确要求“根据某报告”时优先限定该文件；比较/综合问题可跨本批文件检索。
- 提示词要求区分报告事实、分析推断、缺失信息，注明日期和计量口径，检查表格附注与计算矛盾。
  文档正文放在证据数据字段，明确不把其中的要求当作程序指令。
- 答案仅列实际使用的有效证据编号，不再将所有候选文档都显示成支持结论的参考来源。
  去掉模型自评百分比。编号校验不等于自动证明事实正确，仍应对照原文复核。
- 保持现有 DeepSeek 与嵌入模型配置，不下载新的嵌入模型。页面默认模式兼容
  `.env` 中的 `DEEPSEEK_THINKING`，页面内可切换。深入模式使用有界的思考强度与 18,000 token
  上限；达到思考长度上限时，自动使用相同证据重试一次标准回答并注明。
- 深入分析生成初稿后，再由标准模式对照同一批原文核查数字、引用、表格归属与脚注。
  此步骤增加一次 API 请求；若核查未完成，页面明确标出“初稿”。自动核查仍不能替代人工复核。
- 向量索引失败时保留关键词检索，并在处理状态提示；API 失败时保留证据面板。

## 验证

使用同一 Conda 解释器：

```powershell
& 'C:\Users\18136\.conda\envs\pythonproject8\python.exe' -s -m unittest -v test_rag_engine test_ui_flow
```

`test_rag_engine` 覆盖上传范围、去重、空白页、英文报告召回、限定来源、引用校验等。
`test_ui_flow` 使用真实本地 Gradio 上传和队列、测试模型，验证页面回调和两个会话隔离，
完成后自动关闭测试端口 7865；不调用外部模型。

`validate_rag.py` 使用本机截图对应的五份 PDF 和真实嵌入模型验证检索；
加 `--live` 才发送研究问题到配置中的 DeepSeek，产生实际 API 用量。

新辅助文件可以保留，不影响旧脚本。
